## Зачем нужен Project KB

При работе с кодовой базой агент ищет определения, собирает импорты и выбирает файлы для чтения. Эти сведения приходится связывать с конкретным состоянием проекта: доступный результат может уже не соответствовать изменённым исходникам.

Project KB строит структурный снимок Python-проекта и предоставляет запросы к нему: найти класс, получить сведения о файле, выбрать записи с нужными полями или посчитать их. Ответы MCP связаны с одним закреплённым снимком; отдельная строгая проверка определяет его актуальность относительно рабочей копии.

Целевой Python-код не импортируется и не выполняется. Полная индексация и хранение отделены от исходников.

## Как работает

```mermaid
flowchart LR
    Source["Python-проект"] --> Index["Полная<br/>индексация"]
    Index --> Snapshot[("Снимок SQLite")]
    Agent["AI-агент"] <-->|"запрос / ответ"| MCP["MCP · чтение"]
    MCP --> Snapshot
```

Оператор подготавливает снимок через CLI. MCP читает явно выбранный артефакт и возвращает структурные данные с его идентичностью. Проверка `status --verify strong` выполняется отдельно: закреплённость снимка не означает, что исходники с тех пор не изменились.

PyCharm MCP также умеет искать символы и анализировать связи. Особенность Project KB — контракт чтения сохранённого снимка с проверяемым происхождением данных. [Сравнение подходов и полная схема показа](PRESENTATION.md#чем-отличается-от-поиска-и-pycharm-mcp).

## Возможности

| Задача | Интерфейс |
| --- | --- |
| Зарегистрировать проект и построить полный снимок | `register`, `index --full` |
| Проверить состояние и актуальность | `status --verify strong` |
| Найти определение класса или функции | `symbols`, MCP `find_symbols` |
| Получить импорты и карточку файла | `imports`, `inspect`, MCP `inspect_paths` |
| Выбрать файлы и структурные записи, посчитать или сгруппировать их | MCP `query_structural_records` |
| Получить идентичность и происхождение снимка | MCP `get_snapshot_metadata` |

MCP поддерживает выбор полей, ограничения числа записей и размера ответа, постраничное чтение и пакетные запросы.

**Промежуточные снимки задачи.** Внутренний экспериментальный механизм сохраняет исходную структуру и последующие рабочие поколения вне Git. Агент может сравнивать изменения файлов, определений и импортов между шагами, не создавая служебные коммиты. [Схема и границы механизма](PRESENTATION.md#промежуточные-снимки-задачи).

```mermaid
flowchart LR

    Query --> Answer["shop/services.py<br/>класс и строки"]

```

[Презентация](PRESENTATION.md#примеры-на-мини-проекте) показывает исходники, реальные результаты запросов, дерево файлов и обнаружение устаревшего снимка.

## Быстрый старт

Нужны **Python ≥3.14**, **uv** и **Git**. Из корня репозитория:

```text
uv sync
uv run pkb --help
```

<details>
<summary>Справка CLI: команды и пояснения на русском</summary>

![Команды Project KB в PowerShell](docs/assets/cli-help.png)

Команда запускается как `uv run pkb <команда>`. Например, `uv run pkb inspect --help` показывает её параметры.

| Команда | Когда нужна | Что получаем |
| --- | --- | --- |
| `version` | Узнать версию программы | Номер установленной версии |
| `capabilities` | Посмотреть доступные возможности | Что реализовано в текущей версии |
| `register` | Подключить локальный Git-проект | Регистрацию проекта по имени и пути |
| `projects` | Найти подключённый проект | Список зарегистрированных проектов |
| `index --full` | Собрать структурную карту | Полный снимок файлов, определений и импортов |
| `status` | Проверить состояние проекта | Состояние регистрации и снимка; с `--verify strong` — его актуальность |
| `symbols` | Найти класс, функцию или метод | Имя, файл и строки определения |
| `imports` | Разобраться в зависимостях файла | Импорты и найденные пути к модулям |
| `inspect` | Посмотреть структуру одного файла | Определения, импорты и ошибки разбора |
| `relink` | Обновить путь после перемещения проекта | Привязку к новому расположению |
| `unregister` | Убрать проект из Project KB | Удаление регистрации и его хранилища Project KB; исходники сохраняются |

</details>

Воспроизводимый пример с отдельным временным Git-проектом и хранилищем:

```text
uv run python examples/order_demo/run_demo.py
```

Сценарий выполняет регистрацию, индексацию, строгую проверку, запросы CLI и MCP, затем демонстрирует устаревание снимка. Для просмотра созданных файлов используйте `--keep-temp`; для структурированного результата — `--json`. [Команды и устройство примера](examples/order_demo/README.md).

Для собственного Git-проекта:

```text
uv run pkb register my-project /path/to/repository
uv run pkb index my-project --full
uv run pkb status my-project --verify strong
uv run pkb symbols my-project --name OrderService
```

Для запуска отдельного MCP-процесса передаются путь снимка, его идентичность, SHA-256 и исходный коммит. [Настройка и границы MCP](docs/ARCHITECTURE.md#55-закреплённое-оператором-чтение-через-mcp).

## Ограничения

- Поддерживается полная структурная индексация Python/Git-проектов; инкрементальная индексация не реализована.
- Обобщённый и семантический поиск, экспорт и пакеты контекста отключены.
- MCP работает только на чтение закреплённого снимка и не выбирает автоматически последний.
- Читаемый снимок может быть устаревшим; `CURRENT` относится к моменту успешной строгой проверки.
- Структурные данные дополняют чтение исходников и анализ IDE; они не заменяют полноценную семантическую модель PyCharm.

Версия `0.1.0` — замороженный исследовательский прототип. Дальнейшая разработка приостановлена из-за ограниченного времени и ресурсов.
